## 三餐组合算法（核心）

**两阶段：餐位全枚举 Top-K + 日期间随机重组**

1. 阶段一：每个餐位（早30%/午40%/晚30%）枚举全部 (主餐, 小食, 饮品) 组合，允许分量为空（= 轻食餐位），按营养偏差评分取 Top-40。组合空间约 840，全枚举无压力。
2. 阶段二：400 轮重组——每轮按 `餐位分 + 全天去重惩罚(12/项) + 多样性扰动(0~6) + 预算软压力(8×溢出额)` 选组合，全天评分（热量100/蛋白60/脂肪25/钠10/预算12 权重）保留最优。

**实测性能**：约 80-200ms/次，误差见下。

## 调参过程中的领域发现（README 素材）

- **预算硬约束不可行**：麦当劳单品 ¥14-26，三餐 ¥100-130 是常态；预算必须做软约束并输出 `over_budget` 标记诚实告知。
- **蛋白缺口是真实痛点**：快餐蛋白密度低，1592kcal 减脂目标最多凑到 ~95g 蛋白（目标 126g），报告页应展示"蛋白缺口 + 补充建议"（纯牛奶/玉米杯是性价比之选）——这正好是产品的差异化叙事。
- **钠超标是普遍现象**：三个汉堡 ≈ 2800mg，超膳食指南 2000mg；报告页钠进度条是"劝退/劝换"的关键可视化。
- **早餐时段问题**：晚间菜单无早餐品类，早餐餐位自动回退主食+轻食组合；`now-time-info` 用于给出时段提示。
- 菜单与营养表名称对齐：归一化（全角括号/引号/™/空格）→ 全等 → 前缀 → 包含 + 规格偏好（中杯>小杯）；同营养项全天只挂一个菜单项。

# 优惠券与端到端开发（2026-10-10 续）

## 已验证（真实 MCP 调用）

- **calculate-price 打通**：items = `[{productCode, quantity, couponId?, couponCode?}]`；金额单位为**分**；返回逐品 subtotal、整单 discount、takeWayList。
- **CLI 端到端跑通**（`main.py`，Token 走环境变量 MCD_MCP_TOKEN，不落仓库）：营养缓存 → 门店 → 菜单对齐 → 规划 → 官方算价。**菜单价与官方算价完全一致**，验证规划器价格精度。

## 新增文件

- `src/coupon.py`：门店可用券查询 + 券-商品直配算价 / 卡包查询 / 无券算价
- `src/main.py`：CLI 全流程入口，营养库与菜单本地缓存（带 schema 版本号）

## 用券链路验证（2026-10-10 晚；结论已于 2026-10-11 更正）

**初版结论（错误，已废弃）：** 曾记录为「券存在隐性使用条件，算价阶段可能报 600012」，
并据此采用「每券 × 每商品位」的盲试算价（上限 60 次）。

**更正后的真实根因（2026-10-11 实测）：**

| 数据来源 | 结果 |
|---|---|
| `auto-bind-coupons` 领取结果里的 couponCode | 报 `600012 未找到优惠券或已赠送给好友` |
| `query-store-coupons(storeCode, orderType, beType)` 返回的 couponCode | **成功：原价 ¥11.9 → 应付 ¥9.9** |

- **不是时段问题，也不是券有隐性条件**——是**券码取错了接口**。同一 `couponId`，
  领券结果里的码无效，门店/订单维度接口返回的才是可核销码。
- `query-store-coupons` 一次返回「可用券 + 有效券码 + 适用商品编码」，可直接做
  **券-商品直配**，无需盲试；`--bind` 由此降级为「顺便领券」的可选动作。
- 官方工具描述明确：`query-my-coupons` **不做门店/渠道校验**，不承诺可用于当前订单，
  只能用于展示。

**验收：算价主链路 + 门店券直配链路 ✅ 完整可用；盲试逻辑已移除。**

# 可视化营养报告页（2026-10-10 晚）

## 交付
- `src/report.py`：报告生成器——Chart.js 雷达图（五维达成率，钠为反向指标）+ 三餐热量环形图 + 五项营养进度条（绿/橙/红三态）+ 钠超标/蛋白缺口/预算三类洞察 + 已用券信息 + 门店与官方算价。1080px 分享卡片版式（含响应式降级），麦当劳品牌黄渐变头部；Chart.js 离线时自动退化为数据表。
- `src/main.py` 新增 `--report [路径]`：规划完成后一键生成报告 HTML。

## 设计决策
- **雷达图钠维度做反向换算**（上限/实际×100），超标时数值 <100，雷达自然内凹，比直接展示 mg 更直观。
- **进度条三态语义**：热量/蛋白/脂肪/碳水 80-120% 绿、低于 80% 橙（缺口）、高于 120% 红；钠 ≤100% 绿、超标红——与「营养师点评」文案联动。
- **洞察即卖点**：蛋白缺口给出纯牛奶补齐建议、钠超标给次日选品建议，这是 README 里"诚实展示快餐营养现实"差异化叙事的报告端落地。
